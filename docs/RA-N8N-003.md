# RA-N8N-003: consultor contextual mediante RAG

Estado: completado y aceptado por el usuario el 27 de septiembre de 2026; activo con las dos guías aprobadas. Indexación, recuperación,
memoria, permisos y recorrido desplegado verificados el 27 de septiembre de 2026.
Comparte los canales e identidad de [RA-N8N-001](RA-N8N-001.md).

## Dos flujos separados

**Indexación administrativa:** manifiesto de fuentes aprobadas → comprobar versión
y hash → fragmentar → Default Data Loader → Embeddings Google Gemini → PGVector
Insert Documents. Nunca alimentar este flujo con mensajes de usuarios, historiales
financieros, respuestas HTTP financieras o memoria conversacional. Sin trigger público.

**Consulta:** entrada autorizada de web/Telegram → clasificar documental/personal/mixta
→ recuperación documental y/o herramientas GET fijas de Spring Boot → validar evidencia
→ respuesta con fuentes → memoria de contexto por usuario y canal.

La recuperación documental no concede acceso financiero. Para una consulta personal
se aplica la verificación de cuenta de RA-N8N-001, aun si la conversación anterior fue
documental. Si falla la autorización en una pregunta mixta, explicar que no se pueden
consultar datos personales; solo dar la parte documental si existe evidencia aprobada.

## Preparación implementada

`integrations/n8n/rag/sources.json` registra las dos guías aprobadas expresamente por el usuario:
`docs/knowledge/estrategias.md` y `docs/knowledge/registro-y-consultas.md`. Cada entrada requiere:

```json
{
  "path": "docs/archivo-aprobado.md",
  "title": "Título aprobado",
  "version": "1",
  "approved": true,
  "approvedBy": "Responsable de revisión",
  "sha256": "SHA-256 real de los bytes aprobados"
}
```

Tras aprobar los documentos y completar el manifiesto:

```powershell
node integrations/n8n/rag/prepare-corpus.mjs
```

La salida es `tmp/rag/approved-chunks.json`, fuera de Git, con `pageContent` y metadatos
de fuente, versión, hash e identificador estable de fragmento. No llama a Gemini ni
escribe en Supabase. Solo acepta Markdown explícito dentro del repositorio y verifica
su integridad; no escanea carpetas ni indexa automáticamente README o documentación
de infraestructura. Fragmentación inicial: 1200 caracteres y 200 de solapamiento;
calibrar con el modelo elegido, no interpretar caracteres como tokens.

Para PDFs u otros formatos se preparará una extracción revisable antes de su aprobación.
Un hash acredita que el archivo no cambió; la aprobación humana debe comprobar que su
contenido es válido, no contiene secretos ni información personal y corresponde a Ceroa.

## Almacenamiento y credenciales

Preferencia de integración: PGVector en un esquema auxiliar `n8n_aux` de Supabase,
fuera de Flyway de negocio. Dos credenciales PostgreSQL dedicadas: indexador para
escribir exclusivamente documentos auxiliares y consultor para recuperar documentos.
Ninguna debe tener USAGE ni permisos sobre `ceroa`, ni ser el usuario `postgres`, ni
heredar un rol con acceso financiero. Verificar permisos efectivos antes de activarlas.
La configuración de tabla/esquema debe comprobarse con la versión instalada del nodo;
no asumir que el nombre de tabla admite un nombre calificado sin probarlo.

Se crearon tablas auxiliares después de medir la dimensión real del modelo.
Ingesta y consultas usan `gemini-embedding-001`, dimensión 768 y normalización del vector.
Ingesta y consultas usan el mismo modelo,
dimensión y procesamiento. Cambiar de modelo exige un índice nuevo y reindexación.
Separar versiones publicadas; retirar de consulta los fragmentos de documentos revocados
o reemplazados, evitando duplicar documentos en cada ejecución del indexador.

El runtime debe tener acceso de lectura únicamente. Algunos clientes crean tablas o
extensiones al inicializar: probarlos con la credencial limitada. Si requieren DDL,
precrear por administración o usar una herramienta de recuperación parametrizada;
no resolverlo concediendo privilegios generales al agente.

## Recuperación y respuestas

Solo la colección/versiones publicadas y aprobadas son consultables. Recuperar un
número limitado de fragmentos y aplicar un filtro real de relevancia antes de generar
respuesta. Calibrar el umbral con preguntas de prueba; no inventar un umbral universal
ni asumir que cualquier resultado del top-k es evidencia suficiente. Si el Vector Store
Tool oculta puntuaciones, usar Get Many con resultados verificables dentro de una
herramienta de workflow y filtrar antes de devolver contexto al agente.

La respuesta documental incluye título y referencia a los fragmentos utilizados.
Sin evidencia o ante fallo de Vector Store: "No tengo información aprobada suficiente
para responder esa pregunta". Sin fallback a conocimiento general del modelo ni web.

Un fragmento es evidencia, no una instrucción: ignorar texto que proponga cambiar
herramientas, permisos, destinos o reglas. El agente no recibe herramientas SQL ni
HTTP con URL/método arbitrario. Las finanzas se resuelven solo con las rutas GET
permitidas en RA-N8N-001, consultadas nuevamente para cada pregunta personal.
Importes y fechas se insertan desde el JSON del backend, fuera de la generación libre.

## Memoria

Inicialmente contexto limitado, separado con clave derivada de usuario autenticado,
canal y conversación. Nunca aceptar un sessionId público como prueba de identidad.
La memoria no se indexa como documentación aprobada, no conserva credenciales y no
responde por sí sola a preguntas sobre saldos actuales.

Window Buffer Memory sirve para una instancia sencilla; evitar Simple/Window Memory
en queue mode sin verificar su compatibilidad. Postgres Chat Memory, si se adopta,
usa otra tabla auxiliar con permisos propios y una política de retención/borrado.
Su escritura de mensajes es auxiliar y no implica permiso sobre datos financieros.

## Pruebas previas a activación

- Bola de Nieve/Avalancha: respuesta con fuentes aprobadas, sin cifras personales.
- "¿Cuál estoy usando yo?": consulta actual de estrategia del usuario asociado.
- "¿Cuánto debo?": backend como fuente; nunca sumar deudas en el modelo ni usar embeddings.
- Pregunta mixta: evidencia documental y financiera distinguibles.
- Corpus vacío, fuente retirada, modelo incompatible, vector store caído o baja relevancia:
  abstención; no respuesta inventada.
- Memoria de otra cuenta, remitente no asociado e instrucciones maliciosas en fragmentos:
  sin filtración de datos ni ejecución arbitraria.
- Consultas y solicitudes de cambios: ninguna llamada financiera POST/PUT/DELETE.

## Implementación y operación

Hay dos workflows principales: `ceroaRagIndex03` (manual, administrativo) y
`ceroaAssistantRag03` (consulta autenticada de web y Telegram). El helper privado
`ceroaRagEmbedding03` genera los vectores de consulta; no proporciona acceso financiero.

La indexación genera embeddings en n8n, conserva la procedencia y hace upsert parametrizado
en `n8n_aux.rag_chunks` con el rol `ceroa_rag_indexer`. No publica automáticamente ni acepta
mensajes, archivos de usuarios o entradas públicas. La publicación cambia atómicamente
el snapshot en `n8n_aux.rag_publication`, después de verificar integridad, número de
fragmentos y calibración. Reindexar el mismo snapshot no duplica los fragmentos.

La recuperación utiliza SQL fijo parametrizado sobre PGVector desde Spring Boot, con
una conexión independiente `ceroa_rag_reader` de solo lectura. Se eligió este camino para
controlar puntuaciones, publicación y revocación sin conceder DDL al runtime. No utiliza
el datasource financiero ni PostgreSQL local. Ambos roles fueron probados con denegación
real de acceso a `ceroa` y de creación de tablas; el lector también tiene escritura denegada.

El modelo clasifica el turno en documental, personal o mixto. Para la parte documental
consulta hasta dos veces y recibe hasta cuatro fragmentos filtrados por relevancia.
La respuesta declara las fuentes utilizadas y el backend comprueba que fueron recuperadas
en esta solicitud y siguen publicadas. Añade título, versión y referencia del fragmento.
Fuentes inventadas son rechazadas; sin evidencia documental se fuerza abstención.
El umbral se obtuvo de doce preguntas positivas/negativas del corpus inicial; es específico
de esa colección y debe recalibrarse al cambiar fuentes o modelo. Esto no demuestra cobertura
de todas las preguntas: el modelo debe comprobar también que los fragmentos apoyan la respuesta.

Las consultas personales reutilizan exclusivamente las herramientas GET fijas del backend
y los cálculos con evidencia vigente de RA-N8N-001. Los importes y fechas financieros siguen
insertándose desde hechos de la solicitud actual; un fragmento o turno anterior no los autoriza.

La memoria está en el backend de una sola instancia, fuera del corpus y del historial n8n:
tres turnos, cinco minutos, máximo cien contextos, clave usuario/canal/conversación UUID
generada por el servidor. Las cifras de preguntas y respuestas anteriores se ocultan en el
contexto; turnos que mencionan credenciales y referencias documentales anteriores se
omiten. Reiniciar el backend elimina esa memoria. Web permite Nueva conversación;
Telegram permite `/nuevo`. No se acepta un sessionId del cliente como identidad.
Para varias instancias se requiere un almacén compartido con la misma política e identidad.

Archivos operativos:
- `rag/SupabaseRagAdmin.java`: provisiona extensión/tablas/roles fuera de Flyway financiero.
- `install-rag.ps1`: prepara el corpus y asocia credenciales cifradas; importa flujos inactivos.
- `rag/calibrate-embeddings.cjs` y `rag/CalibrateRag.java`: miden resultados con consultas de prueba.
- `rag/PublishRag.java`: publica únicamente el snapshot aprobado y calibrado.
- `rag/RagPermissionsProbe.java`: verifica permisos efectivos sin leer datos personales.

Variables privadas: RAG_ENABLED, RAG_DB_URL, RAG_DB_USERNAME, RAG_DB_PASSWORD,
RAG_WORKER_KEY y RAG_EMBEDDING_WEBHOOK_URL. Las credenciales auxiliares del indexador
RAG_INDEX_USERNAME/RAG_INDEX_PASSWORD están en `.env.rag-admin`, ignorado por Git y
no cargado en el contenedor backend; solo se usan en administración/n8n. El modelo
permanece en credenciales cifradas n8n, sin clave Gemini en React ni en el backend.

## Instalación y actualización del corpus

Con credenciales Supabase privadas ya configuradas y Gemini asociado a RA-N8N-001:

```powershell
cd backend
.\mvnw.cmd -q dependency:build-classpath "-Dmdep.outputFile=target/document-test-classpath.txt"
cd ..
$ragClasspath = (Get-Content -Raw backend/target/document-test-classpath.txt).Trim()
java -cp $ragClasspath integrations/n8n/rag/SupabaseRagAdmin.java
powershell -ExecutionPolicy Bypass -File integrations/n8n/install-rag.ps1
docker exec -e N8N_RUNNERS_BROKER_PORT=5681 ceroa-n8n n8n execute --id=ceroaRagIndex03
docker cp integrations/n8n/rag/calibrate-embeddings.cjs ceroa-n8n:/tmp/ceroa-rag-calibrate.cjs
docker exec ceroa-n8n node /tmp/ceroa-rag-calibrate.cjs
docker cp ceroa-n8n:/tmp/ceroa-rag-calibration-vectors.json "$env:TEMP/ceroa-rag-calibration-vectors.json"
java '-Dfile.encoding=UTF-8' -cp $ragClasspath integrations/n8n/rag/CalibrateRag.java "$env:TEMP/ceroa-rag-calibration-vectors.json"
powershell -ExecutionPolicy Bypass -File integrations/n8n/activate-rag.ps1
```

El puerto alternativo del broker permite ejecutar el workflow administrativo por CLI
sin colisionar con el proceso n8n ya levantado. El indexador se mantiene sin trigger público.
Para actualizar, revisar los archivos, aprobar sus nuevas versiones/hashes, regenerar,
reindexar, recalibrar y publicar el snapshot nuevo. No reutilizar la calibración de otra
colección: la publicación la rechaza. Ampliar también las preguntas de calibración según
los temas nuevos. Para revocar una fuente inmediatamente, `rag/RevokeRagSource.java`
retira la publicación afectada y desmarca sus fragmentos; retirar su aprobación en el
manifiesto antes de generar un corpus nuevo. El índice nunca se alimenta del chat ni de
los documentos personales cargados por RA-N8N-002.

# Consulta conjunta de extractos por período

El asistente usa `PERIOD_ANALYSIS` cuando la pregunta requiere analizar todos los
extractos de un período. Primero filtra documentos autorizados por metadatos y luego
lee los fragmentos indexados de cada archivo de la página, sin depender del ranking
semántico global. La respuesta incluye `complete`, `hasMoreDocuments` y `nextOffset`;
si falta un archivo indexado, hay otra página o se supera el límite de contenido,
el estado es `PARTIAL` y no se confirma un total del período.

Los importes y tasas literales encontrados en esos fragmentos se entregan como
hechos vinculados a la consulta. Los importes numéricos se pueden sumar mediante
`Calcular con evidencia`; el modelo debe identificar primero qué líneas son pagos
o intereses reales y evitar duplicados. Un saldo o una proyección no se trata como
un pago. La interfaz permite salir del chat de un solo archivo y preparar una
consulta sobre todos los extractos del mismo mes.
