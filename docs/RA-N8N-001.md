# RA-N8N-001: analista financiero por voz y texto

Estado: implementación completada y aceptada por el usuario el 27 de septiembre de 2026.
Asistente web y Telegram funcionando por texto y audio, con análisis financiero,
formato de montos y vinculación segura. Workflows publicados en n8n local; Telegram usa
el túnel HTTPS temporal de pruebas. Las escrituras financieras no están habilitadas.
Requerimiento independiente de RA-N8N-002/003/004/005.

Base financiera activa: exclusivamente Supabase, perfil `supabase`, esquema `ceroa`.
Telegram → n8n → API Spring Boot → Supabase. Los workflows no consultan PostgreSQL
local ni acceden directamente a las tablas financieras. n8n conserva únicamente su
configuración interna en SQLite dentro de su volumen Docker.
El contenedor antiguo `ceroa-postgres` quedó detenido y con reinicio automático desactivado;
sus datos se conservaron. La prueba PostgreSQL desechable de la auditoría fue independiente
del entorno de la aplicación y ya se eliminó; no cambió la conexión activa a Supabase.

## Arquitectura activa

React FAB → sesión/CSRF Spring Boot → webhook privado n8n → transcripción si audio
→ preparación del contexto → AI Agent Gemini con herramientas de lectura y cálculo
→ respuesta estructurada → validación de evidencia Spring Boot → usuario original.

El agente ya no clasifica preguntas dentro de una lista de respuestas predefinidas.
Elige y combina fuentes, compara opciones, analiza presupuesto, explica prioridades
y atiende seguimientos. Genera su respuesta para la pregunta concreta. Si faltan datos,
debe explicarlo o pedir aclaración. No puede garantizar respuestas sobre cualquier tema
ni consultar información externa en tiempo real: las herramientas acceden a Ceroa.

Modelo activo para análisis y transcripción: models/gemini-3.5-flash-lite, disponible y
probado con esta credencial. Gemini 3.8 Flash presentó errores de alta demanda en las pruebas.
Credencial privada n8n: Ceroa Gemini. Ninguna API key llega al navegador. El Assistant
de configuración de n8n permanece independiente de este workflow.

## Herramientas y cálculos

- Consultar datos financieros: summary, profile, debts, payments, upcoming, strategy,
  comparison y progress. Puede paginar listas y consultar distintos períodos de progreso.
  Delega en los servicios existentes y conserva sus validaciones y permisos del plan.
- Calcular con evidencia: suma, resta, multiplicación, división, mínimo y máximo de
  valores numéricos obtenidos en esta solicitud, usando BigDecimal en backend.

Las deudas incluyen tasas normalizadas por RateNormalizationService: EA, MV y NAMV
se comparan en efectivo anual; las indexadas sin índice disponible no son comparables.
Las proyecciones proceden de StrategyService; la aritmética no reemplaza la amortización.
No hay un motor de proyecciones arbitrarias que permita garantizar cualquier escenario.

La preparación identifica cifras de la pregunta y las marca como supuestos del usuario,
con notación colombiana (coma decimal, punto de miles). El agente debe aclarar cifras
ambiguas y distinguir hipótesis de datos registrados. Porcentaje y meses/año son constantes.
Cada dato recibe una referencia temporal. Gemini redacta usando referencias para cifras,
fechas y nombres con números; backend las sustituye por valores reales, conservando
el valor decimal. La presentación usa puntos de miles y coma decimal (1.250.000 y
28,7%); elimina ceros decimales innecesarios y conserva fechas y años sin agrupar.
Rechaza referencias desconocidas/nulas y cifras literales sin evidencia.
Esto verifica procedencia numérica, no demuestra que cada interpretación o recomendación
sea correcta. Debe explicar supuestos, cobertura incompleta e incertidumbre.

## Identidad, privacidad y límites

Contexto de 180 segundos ligado al usuario autenticado. El Header Auth del worker
(X-Ceroa-Assistant) no permite una sesión web ni CRUD financiero. No acepta userId como
identidad, SQL o URLs arbitrarias. Revalida cuenta activa en lectura, cálculo y finalización.
Rutas privadas bajo /api/v1/assistant-tools/requests/{id}:

- POST /prepare: registra texto/transcripción y devuelve evidencia de los supuestos.
- GET /data: consulta dataset, período y páginas de 25 elementos.
- GET /calculate: calcula con referencias del contexto.
- POST /complete: valida evidencia y cierra el resultado; no modifica las finanzas.

GET /query conserva compatibilidad con la versión anterior de consultas canónicas;
el workflow activo no lo usa ni tiene herramientas conectadas a él.
Una consulta simultánea por usuario, cinco solicitudes/minuto, 100 contextos activos,
16 lecturas/cálculos y 4000 hechos por solicitud. Lecturas idénticas usan caché temporal.
Ocho iteraciones del agente, timeout de workflow 140 segundos y backend 150 segundos.
Tras completar no se aceptan herramientas; al finalizar o fallar se elimina el contexto.

Memoria: tres intercambios por cuenta durante cinco minutos, hasta 100 cuentas, solo en
backend. Sirven para referencias conversacionales, nunca como evidencia financiera actual.
Un reinicio limpia la memoria. Varias réplicas requieren almacenamiento compartido o afinidad.
Gemini procesa preguntas, audio y datos financieros necesarios, como informa el panel.
Se excluyen identificadores de cuenta/deuda, números de cuenta y notas libres de las
herramientas. Los nombres de deudas y sus cifras pueden llegar al modelo. Audio inline,
sin Google Files. n8n no guarda ejecuciones exitosas, fallidas ni manuales del workflow.
Chat y audios viven en memoria del navegador, sin localStorage, y se desmontan al salir
o cambiar usuario.

## Interfaz, fallos y modificaciones

Texto hasta 2000 caracteres y audio hasta 4 MiB: WebM, OGG, WAV, MP3 y MP4. Grabación
muestra barras de frecuencia y tiempo. Enviar detiene y envía. A los 60 segundos conserva
el audio para escucharlo y enviarlo manualmente. El audio enviado queda reproducible en
chat. Cerrar cancela la grabación o permiso pendiente sin enviar. Micrófono requiere
permiso y localhost o HTTPS. Errores de dispositivo, permiso, tamaño y audio se muestran.
Si falla transcripción, modelo, autorización o evidencia, no se inventa un resultado ni
se vuelve a un listado fijo. Transcripción admite dos intentos; el agente no se reintenta
entero automáticamente. Puede explicar modificaciones hipotéticas, pero no crear, editar,
eliminar ni ejecutar pagos. Un sí no realiza cambios. Futuras escrituras requieren un
contrato separado con aprobación concreta, vinculada, caducable y de un solo uso.

## Configuración

Variables privadas: ASSISTANT_ENABLED=true,
ASSISTANT_WEBHOOK_URL=http://n8n:5678/webhook/ceroa-assistant-v1 y ASSISTANT_WORKER_KEY
aleatoria de al menos 32 caracteres. La clave se asocia a Header Auth del webhook y
nodos del puente; Gemini tiene su propia credencial. La plantilla .env.example está desactivada.
Workflow: RA-N8N-001 - Analista financiero conversacional; id ceroaAssistant01.
Plantilla portable sin credenciales: integrations/n8n/assistant-web.json.
build-assistant-workflow.mjs solo reconstruye la plantilla. Al importarla, reasociar
credenciales; no sobrescribir una instalación configurada perdiendo sus asociaciones.

```powershell
docker compose -f docker-compose.yml -f docker-compose.n8n.yml -f docker-compose.n8n-sandbox.yml up -d backend frontend n8n sandbox-runner-1
```

No depende del Assistant de n8n, SearXNG ni PostgreSQL de n8n. La instalación local
funciona mientras Docker y la computadora están encendidos.

worker sin acceso financiero, cuenta inactiva, contexto consumido, audio inválido, límites,

## Telegram local

Flujo `assistant-telegram.json`, generado por `build-telegram-workflow.mjs`:
Telegram Trigger → chat privado → verificar vinculación → descargar voz si corresponde
→ analista de Ceroa → confirmar vinculación antes de enviar → respuesta al chat verificado.
Usa la credencial Telegram API `Ceroa Telegram`; el token permanece cifrado en n8n.
No exportar credenciales descifradas ni guardar el token del bot en el repositorio.

Desde Perfil → Telegram se autoriza la consulta y se crea un enlace de un solo uso,
vigente cinco minutos. En la base solo se guarda su hash. Vinculación uno a uno,
límite de intentos, códigos inválidos/caducados rechazados, recibos para evitar procesar
updates repetidos y desvinculación desde la web o `/desvincular`. Solo chat privado con
remitente igual al destinatario; una cuenta inactiva pierde acceso. No se acepta userId
del mensaje ni permisos CRUD. Voz Ogg: máximo 60 segundos y 4 MiB, autorizada antes de
descargar. El análisis usa las mismas herramientas y validación de evidencia de la web.

`docker-compose.telegram-local.yml` añade Cloudflare Quick Tunnel y un proxy que solo
admite POST al webhook exacto con su cabecera secreta. El panel de n8n, otras rutas y el
webhook financiero de la web no quedan expuestos. `.env.telegram-local` (ignorado por Git)
contiene UUID privados del trigger/webhook, secreto derivado y URL temporal; no contiene
el token del bot. No publicar el flujo instalado: n8n deriva el secreto del ID privado
del trigger, por eso la plantilla portable lleva marcadores que se reemplazan al instalar.

Para refrescar la URL si se reinicia el túnel:

```powershell
.\integrations\n8n\install-telegram-local.ps1
```

El script obtiene la URL del contenedor, asocia credenciales existentes, importa/publica
el flujo y reinicia n8n. Requiere `.env.telegram-local` configurado, el asistente web ya
instalado y los contenedores de túnel activos. La dirección temporal sirve para desarrollo;
Docker, la computadora y el túnel deben permanecer encendidos.

Verificado: enlace privado, consentimiento, CSRF, caducidad, uso único, aislamiento,
desvinculación, inactividad, deduplicación y revocación de entrega. Se probó la URL real:
panel/otras rutas/sin secreto → 404; webhook autorizado → 200. Fixtures n8n sin enviar
mensajes probaron que una voz sin vinculación no se descarga y que la conversión binaria
a Ogg/base64 funciona. El titular confirmó que todo funciona desde Telegram y dio por
terminada la implementación el 27 de septiembre de 2026, cerrando la validación manual
de vinculación, preguntas y notas de voz.
La interfaz desplegada se comprobó en navegador con la cuenta demo: Perfil → Configurar
Telegram muestra la autorización y el botón de enlace; la sesión de prueba se cerró al
terminar. No se vinculó la cuenta demo ni se enviaron mensajes a chats reales.
