# RA-N8N-001: asistente financiero por voz y texto

Estado: canal web multiusuario implementado y workflow activado en n8n local.
Telegram pendiente de bot y URL HTTPS; no hay canal Telegram ni escrituras activados.
Este requerimiento permanece separado de RA-N8N-002/003/004/005.

## Recorrido implementado

React FAB → POST /api/v1/assistant/messages (sesión + CSRF) → webhook privado n8n
→ transcripción si audio → AI Agent Gemini → Structured Output Parser → validación
estricta → HTTP Request a Spring Boot → respuesta canónica al usuario original.

Modelo confirmado disponible mediante la API: models/gemini-3.8-flash. Credencial
privada n8n: Ceroa Gemini. La API key no está en el repositorio ni se pasa al navegador.
El Assistant de configuración de n8n y el workflow financiero son configuraciones distintas.

El FAB aparece tras autenticación y configuración inicial de cuenta. Acepta texto
hasta 2000 caracteres, archivos de audio de hasta 4 MiB y grabación de hasta 60 segundos.
Formatos: WebM, OGG, WAV, MP3 (audio/mpeg) y MP4. El navegador pide permiso de micrófono;
cerrar el asistente cancela una grabación sin enviarla. La respuesta inicial es texto.
El reconocimiento de voz puede ser incompleto: en ese caso falla sin consultar cifras.

## Identidad y herramientas limitadas

Spring Boot crea un contexto temporal de 120 segundos ligado al usuario de la sesión.
No acepta un userId de entrada como identidad ni comparte el Bearer Auth personal
existente entre cuentas. El modelo tampoco recibe identificadores de otras cuentas.

n8n usa una credencial Header Auth exclusiva del puente (X-Ceroa-Assistant) y el
identificador de contexto emitido por backend para GET
/api/v1/assistant-tools/requests/{id}/query. La ruta solo acepta una enumeración
cerrada: debts, upcoming, payments, strategy, progress, write_request, unknown.
No permite elegir URL, método, SQL, propietario o una operación financiera arbitraria.
El contexto desaparece al completar o fallar la solicitud. Una API key de modelo no
sirve para consultar datos de Ceroa. El header del worker no sirve como sesión web
ni permite entrar al CRUD de automatización.

La herramienta de lectura delega en DebtService, PaymentService, UpcomingDueService,
StrategyService, DashboardService y MonthlyProgressService, sin reemplazar cálculos
ni validaciones. Comprueba de nuevo que la cuenta esté activa. Protecciones: una
consulta simultánea por usuario, cinco solicitudes/minuto por cuenta, máximo 100
contextos activos y tiempo de espera de 90 segundos.

Gemini solo ve mensaje/audio y contexto mínimo de intención previa, no las respuestas
financieras. Spring Boot construye el texto de respuesta con valores del backend,
conservando importes decimales y fechas. No existe un resumen numérico generado
libremente por el modelo. Las listas se limitan a 10 elementos y lo indican cuando
hay más; el saldo total procede de DashboardService, no de una suma hecha por IA.

## Conversación, errores y escrituras

Contexto de seguimiento: última intención durante cinco minutos, separado por cuenta.
No se conserva un historial financiero en n8n ni se usa memoria como fuente de saldos.
El chat del FAB vive en memoria y se desmonta al cerrar sesión/cambiar usuario;
no se guarda en localStorage. Las preguntas y el audio se procesan con Google Gemini,
como informa el panel. El audio se envía inline; no se crea un archivo en Google Files.

Salida inválida del parser, falta de autorización, contexto expirado o error API:
no presentar cifras inventadas. Google puede devolver 503 por alta demanda; el workflow
reintenta como máximo tres veces con pausa de dos segundos dentro del límite global.
El frontend informa el fallo y permite volver a preguntar. No hay fallback que invente
resultados ni una acción financiera que reintentar.

Unknown pide aclaración. Write_request informa que las modificaciones requieren
revisión y confirmación y que este asistente aún solo permite consultas. No existe
una confirmación pendiente ni herramientas POST/PUT/DELETE financieras en esta fase;
un "sí" u "ok" no puede ejecutar escrituras. Las escrituras futuras requieren un
contrato separado con aprobación concreta, vinculada, caducable y de un solo uso.

## Configuración y ejecución

Variables privadas del backend en .env (valores reales excluidos de Git):

- ASSISTANT_ENABLED=true
- ASSISTANT_WEBHOOK_URL=http://n8n:5678/webhook/ceroa-assistant-v1
- ASSISTANT_WORKER_KEY: clave aleatoria de al menos 32 caracteres

La misma clave se guarda únicamente en la credencial Header Auth de n8n para el
webhook y el HTTP Request al puente. Gemini utiliza su propia credencial n8n.
La plantilla .env.example deja el asistente desactivado y la clave vacía.

Workflow instalado: RA-N8N-001 - Asistente web multiusuario (id ceroaAssistant01).
Plantilla portable sin credenciales: integrations/n8n/assistant-web.json.
El generador build-assistant-workflow.mjs reconstruye solo esa plantilla. No reimportar
encima de un workflow configurado sin reasociar sus credenciales: las exportaciones
portables no contienen secretos ni IDs de credenciales de esta instalación.
La captura de ejecuciones exitosas/fallidas/manuales está desactivada.

```powershell
docker compose -f docker-compose.yml -f docker-compose.n8n.yml -f docker-compose.n8n-sandbox.yml up -d backend frontend n8n sandbox-runner-1
```

El sandbox sirve al Assistant de n8n; este workflow usa el AI Agent estándar y no
necesita búsqueda web ni SearXNG. No depende de PostgreSQL local.

El puente temporal es para un solo proceso Spring Boot. Antes de escalar a varias
réplicas se requiere almacenamiento compartido de contextos/límites o afinidad de
solicitudes; un reinicio invalida consultas en curso y limpia contexto de intención.
No se publicaron frontend, backend ni n8n: funcionan mientras Docker está encendido.

## Comprobación

Abrir http://localhost:3000, iniciar sesión y pulsar el botón de chat:
- ¿Cuáles son mis deudas?
- ¿Cuáles son mis próximos vencimientos?
- ¿Qué pagos tengo registrados?
- ¿Cuál es mi estrategia activa?
- ¿Cómo va mi progreso este mes?

Comparar importes/fechas con las vistas de Ceroa. Probar audio y una pregunta desconocida.
Una solicitud de crear/modificar/eliminar debe responder sin realizar cambios.
Las pruebas de integración verifican aislamiento entre dos usuarios, sesión/CSRF,
credencial del worker, rechazo de herramientas arbitrarias, cuenta inactiva, contexto
consumido, salida inventada del modelo, audio inválido y límite por usuario.
Las pruebas de UI verifican texto literal (sin ejecución HTML), errores y cancelación
segura del micrófono. Telegram no está probado porque todavía no está configurado.
