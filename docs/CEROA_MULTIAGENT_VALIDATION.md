## Trazas y métricas

NN registra request IDs sintéticos, workflow principal de fixture, IDs SQLite de especialistas disponibles, herramientas efectivamente seleccionadas, especialidades y latencia. `format_final_json_response` es una herramienta del parser, no otra delegación. UNKNOWN invoca el modelo del orquestador pero ningún especialista; no debe confundirse con una ruta determinista de cero modelos. MAS-01 comprueba esa otra ruta.

Los IDs de ejecución raíz de CLI no están disponibles y se dejan null. Algunos registros SQLite bajo la política de guardado del fixture conservan status running y stoppedAt=null incluso tras el retorno funcional: se documentan tal como se observaron, sin convertirlos en recibos durables de éxito. Las aserciones de salida y las respuestas HTTP determinan el resultado funcional. Los tiempos se obtienen de startedAt/stoppedAt devueltos por CLI o JUnit, no del estado SQLite incompleto.

Para escenarios que solo tienen J no hay request ID ni traza n8n nueva que atribuirles: ambos quedan no disponibles. No se asignan los IDs del benchmark compuesto a una consulta MAS exacta que no lo ejecutó. Las herramientas anunciadas (`availableTools`) se distinguen de las efectivamente seleccionadas (`selectedTool` y `toolsInvoked`).

## Aclaración de contratos para RC2

El Grant es un contrato autorizado ligado al estado del servidor (scopeToken aleatorio, requestId, rol, referencias y vigencia), con callbacks autenticados y validación de alcance en backend. No lleva firma HMAC/JWS. El endpoint versionado de preparación de borradores es `POST /api/v1/workspace-actions/{code}/draft`; las referencias históricas a workspace-proposals/.../gmail-draft no describen el controlador actual. Se conservan los resultados históricos tal como fueron registrados; el manejo HTTP del nuevo controlador se corrige y valida por separado en RC2. Véase [correcciones y validación RC2](CEROA_RC2_CORRECCIONES_Y_VALIDACION_FINAL.md).
